# Заключение о проверке застройщика

Внутренний инструмент Alliance Group: сотрудники проверяют застройщика по 15 блокам, руководитель выпускает заключение (A4, PDF), а клиент проверяет его подлинность по QR-коду или по номеру с контрольным кодом.

## Запуск на своем компьютере

Нужен только Node.js 20 или новее. Аккаунты и Postgres не требуются: база встроена и лежит в `.data/`.

    npm install
    npm run dev

Адрес: http://localhost:4180. Логины и пароли локальных учетных записей создаются при первом запуске в `.data/dev-credentials.txt`.

    npm test

## Разделы

| Раздел | Адрес | Кто видит |
|---|---|---|
| Новая проверка | `#/` | сотрудники |
| Реестр | `#/admin` | сотрудники |
| Документ и его история | `#/doc/<id>` | сотрудники |
| Сотрудники | `#/users` | руководитель |
| Профиль и смена пароля | `#/account` | сотрудники |
| Проверка подлинности | `/verify`, `/v/<токен>` | все, без входа |

## Как проходит заключение

1. Аналитик заполняет форму, черновик сохраняется на сервере автоматически. Можно приложить файлы-подтверждения (PDF, JPG, PNG, WEBP, до 4 МБ).
2. Аналитик отправляет заключение руководителю.
3. Руководитель правит и выпускает его или возвращает с комментарием.
4. При выпуске сервер присваивает номер `ПЗ-ГГГГ-NNN`, сам считает оценку и подписывает редакцию.
5. Правка выпущенного заключения создает новую редакцию. Старая остается в истории, а ее QR-код показывает «Есть более новая редакция».
6. Выпущенное заключение нельзя удалить, только аннулировать с указанием причины.

## Оценка

Подтверждено — полный вес блока, замечания — половина, риск — 0. «Не применимо» доступно блокам 14 и 15 и исключает их из максимума. Всего 60 баллов (первые 13 блоков — прежние 50).

| Уровень | Условие |
|---|---|
| Низкий | меньше 50% баллов или риск по блоку 12 или 14 |
| Средний | меньше 80% баллов, или риск по блоку 9, 11, 15, или замечания по блоку 9, 11, 12, 14 |
| Высокий | все остальное |

Правила лежат в `public/js/core.js`. Их используют и браузер, и сервер, а сервер не доверяет расчетам браузера. Там же находятся проверки согласованности: например, «Подтверждено» нельзя поставить при налоговом долге, а рекомендация не может противоречить уровню.

Записи, импортированные из старого реестра (13 блоков), сохраняют прежние правила подсчета.

## Как защищен документ

- **Контрольный код** — 60 бит HMAC-SHA256 по содержимому редакции с секретом `SIGNING_SECRET`. Без секрета код не подделать.
- **QR-код** содержит случайный токен конкретной редакции.
- **Редакции и журнал действий неизменяемы:** изменение и удаление запрещено триггером в базе. Подмена данных в обход триггера обнаруживается при проверке подписи.
- **Публичная проверка** отвечает только на токен или пару «номер + код», иначе реестр можно было бы выкачать перебором номеров. ФИО она не показывает.

**Секрет `SIGNING_SECRET` нельзя менять и терять:** все выпущенные документы перестанут проходить проверку. Храните его копию в менеджере паролей.

## Выкат на Vercel

Внимание: папка привязана к Vercel-проекту `developer-certificate`, и выкат заменит опубликованную там демоверсию. Для новой версии нужна база Postgres, рекомендуется [Neon](https://neon.tech) (его сертификат проверяется без дополнительной настройки).

1. Создайте базу, скопируйте строку подключения.
2. Создайте секрет подписи и сохраните его копию:

       node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

3. Задайте переменные окружения в Vercel (см. `.env.example`): `DATABASE_URL`, `SIGNING_SECRET`, `PUBLIC_URL`.
4. Создайте таблицы и первого руководителя (пароль передается через переменную, чтобы не попасть в историю команд):

       DATABASE_URL="..." npm run db:migrate
       DATABASE_URL="..." NEW_USER_PASSWORD="..." npm run user:create -- email@example.com "Имя Фамилия" manager

5. Выкатите:

       vercel deploy --prod

6. Проверьте `https://<домен>/api/health`, вход, выпуск тестового заключения и QR-код с телефона.
7. Старый реестр: откройте старую версию, «Экспорт JSON», затем в новой версии «Импорт старого реестра». Записи получат новые контрольные коды.
8. Добавьте на лендинг ссылку на `https://<домен>/verify`.

`PUBLIC_URL` попадает в QR-коды. Задайте постоянный домен до первого выпуска: QR-коды уже напечатанных документов не обновятся.

## Резервные копии

Кнопка «Резервная копия» в реестре выгружает заключения и редакции в JSON (без файлов). Файлы лежат в базе, поэтому основная защита — резервные копии самой базы у хостинга.

## Файлы

- `public/` — интерфейс: `js/core.js` (блоки и правила), `js/app.js` (форма), `js/certificate.js` (листы A4), `js/admin.js` (реестр), `js/staff.js` (сотрудники), `js/verify.js` (публичная проверка), `js/i18n-uz.js` (узбекский текст документа);
- `server/app.js` — API, `server/schema.sql` — таблицы, `server/security.js` — пароли и подпись, `server/dev.js` — локальный запуск, `server/cli.js` — обслуживание базы;
- `api/index.js` — точка входа на Vercel;
- `test/` — тесты правил и API на настоящем SQL.
